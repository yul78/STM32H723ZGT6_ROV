# 水下无人机活动圆导航设计

## 目标

在上位机下发活动圆参数（圆心经纬度、半径）后，单片机侧在固定周期调用导航任务函数，完成以下行为：

1. 判断无人机是否已超出活动圆。
2. 若在圆内，则不移动，两个推进器输出为 0。
3. 若超出活动圆，则自动控制推进器使无人机返回活动圆。
4. 无人机重新进入活动圆后立即停止，不继续逼近圆心。

本设计仅修改 `UserCode/APP/navigation.c` 和 `UserCode/APP/navigation.h`。

## 已知硬件与约束

- JY901 提供 `yaw`，范围为标准欧拉角表示。
- 当 `yaw = 0°` 时，无人机艇体 x 轴朝向为东北 65°，该偏置应写成宏定义，便于后续调整。
- 从东北 65° 朝正北旋转时，`yaw` 为正向增大，最大到 `+180°`；反方向旋转时，`yaw` 为负向减小，最小到 `-180°`。
- 无人机正向即艇体 x 轴方向。
- 无人机为鱼雷形外形，更适合“先转向，再前进”的控制模式。
- 电机 1 为机头左右推进器，作用语义按“纯转向/偏航控制”处理。
- 电机 2 为机尾纵向推进器，负责前进/后退。
- 推进器实际正负方向不在代码中写死，使用宏定义配置极性。

## 对外接口

`navigation.h` 对外提供以下接口：

- `void Navigation_Init(void);`
  - 初始化导航模块内部状态和控制器参数。

- `void Navigation_SetTarget(float center_lat, float center_lon, float radius_m);`
  - 设置活动圆圆心经纬度和半径。

- `void Navigation_Enable(uint8_t enable);`
  - 启用或关闭自动回圈控制。
  - 关闭时立即清零两个推进器输出。

- `void Navigation_Task(void);`
  - 由外部固定周期调用。
  - 内部完成数据读取、出圈判定、控制计算与推进器输出。

- `uint8_t Navigation_IsOutside(void);`
  - 返回当前是否判定为出圈。

- `void Navigation_Stop(void);`
  - 强制停止推进器并清理控制状态。

## 数据结构

`navigation.h` 中定义目标圆参数结构体和导航状态结构体，至少包含：

- 圆心经纬度
- 半径
- 使能标志
- 当前是否出圈标志
- 最近一次距离圆心的距离
- 航向误差
- 前进控制输出
- 转向控制输出

所有对外可调参数均通过宏定义暴露，避免把机械方向、零点偏置和控制阈值写死在实现中。

## 控制策略

### 1. 总体策略

采用“转向优先 + 前进跟随”控制策略：

1. 计算当前位置到圆心的方位角。
2. 根据 JY901 的 `yaw` 和航向零点偏置，得到当前艇体朝向。
3. 计算目标航向与当前朝向之间的误差。
4. 电机 1 根据航向误差输出转向控制量。
5. 电机 2 根据距离圆心的远近输出前进控制量。
6. 当航向偏差过大时，减小或关闭前进量，避免艇体歪着冲向目标。
7. 一旦重新进入活动圆，立即停止两个推进器。

### 2. 出圈与回圈判定

为降低 GPS 抖动造成的边界反复切换，使用回差判定：

- 出圈条件：`distance_to_center > radius + NAV_OUTSIDE_MARGIN_M`
- 回圈完成条件：`distance_to_center <= radius - NAV_INSIDE_MARGIN_M`

当模块处于圈内状态时，仅在超过外侧阈值后进入回圈状态；当模块处于回圈状态时，仅在回到内侧阈值后停止控制。

### 3. 转向控制

电机 1 控制偏航修正：

- 目标输入：航向误差（目标航向 - 当前航向）
- 控制器形式：使用项目现有 `pid_control_t` 结构
- 默认参数策略：以比例控制为主，`ki = 0`，`kd = 0`
- 输出限幅：使用转向最大速度宏定义限制输出
- 输出方向：通过电机 1 极性宏统一映射

之所以默认不启用积分和微分，是因为 GPS 位置环更新慢、噪声较大，先使用 P 控制更稳定、更容易调试。

### 4. 前进控制

电机 2 控制前进/后退：

- 目标输入：距离圆心的超限程度或返回目标距离
- 默认策略：距离越远，前进速度越大，但限幅在最大前进速度宏内
- 航向联动：当航向误差超过阈值时，前进速度按规则减小或置零
- 输出方向：通过电机 2 极性宏统一映射

因为本需求的目标只是“回到活动圆内”，不是高精度停靠圆心，所以前进控制不追求复杂位置闭环，只需保证出圈时能稳定朝圆心方向返回即可。

## 坐标与角度换算

### 1. 经纬度转局部平面距离

在 `navigation.c` 内部把当前位置相对圆心转换为局部平面误差，单位为米：

- 北向误差 `north_m`
- 东向误差 `east_m`

使用小范围近似：

- 纬度差换算为北向距离
- 经度差乘以 `cos(参考纬度)` 后换算为东向距离

该方法适用于活动圆这种小范围区域控制，计算量小，精度足够。

### 2. 目标航向角计算

根据 `east_m` 和 `north_m` 使用反正切函数计算“当前位置指向圆心”的世界坐标航向角。

### 3. 当前航向角计算

当前航向角计算方式为：

`current_heading = jy901_data.yaw + NAV_YAW_OFFSET_DEG`

再对角度统一归一化到 `[-180°, 180°]`，保证航向误差始终取最短转向路径。

## 周期调度

建议外部每 `100 ms` 调用一次 `Navigation_Task()`。

理由：

- 与当前工程内 10 ms 基准 / 100 ms 任务风格一致。
- GPS 更新频率通常较低，100 ms 足够用于边界回圈控制。
- 调度频率不必过高，避免无意义地放大噪声。

该推荐周期写成宏定义并写入头文件注释，方便外部按统一周期调度。

## 失效保护

在以下情况下，导航模块不输出控制，直接停机：

- 自动回圈功能未启用
- 目标半径小于等于 0
- 圆心经纬度未正确设置
- GPS 数据明显无效

GPS 无效判定只做必要边界保护，不引入复杂数据质量状态机，以保持实现聚焦。

## 宏定义项

`navigation.h` 至少提供以下宏定义：

- `NAV_YAW_OFFSET_DEG`
- 电机 1 极性宏
- 电机 2 极性宏
- 最大转向速度宏
- 最大前进速度宏
- 航向对准阈值宏
- 出圈判定回差宏
- 回圈完成回差宏
- 建议任务周期宏

这些宏的目的都是把与机械安装、方向定义、调参相关的内容集中到头文件，方便后续修改。

## 使用方式

外部典型调用流程为：

1. 系统初始化阶段调用 `Navigation_Init()`
2. 上位机下发圆参数后调用 `Navigation_SetTarget(center_lat, center_lon, radius_m)`
3. 启用自动回圈功能 `Navigation_Enable(1)`
4. 在固定周期（建议 100 ms）调用 `Navigation_Task()`
5. 需要停用时调用 `Navigation_Enable(0)` 或 `Navigation_Stop()`

## 测试重点

实现完成后，重点验证以下场景：

1. 目标圆参数未设置时不误动作。
2. GPS 未更新或数据无效时不误动作。
3. 无人机在圆内时推进器始终为 0。
4. 无人机刚刚超出边界时能够进入回圈状态。
5. 航向偏差较大时，先转向，再逐步增加前进速度。
6. 回到圆内后推进器立即停止。
7. 边界附近不会因 GPS 抖动频繁启停。

## 范围控制

本次实现只覆盖“活动圆越界回圈”能力，不扩展以下内容：

- 不实现自动逼近圆心
- 不实现路径规划
- 不实现多航点巡航
- 不实现复杂 GPS 质量评估
- 不改动现有 GPS、JY901、PID 或控制模块文件
